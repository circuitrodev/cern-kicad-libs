# Mirror scripts

Both scripts use only the Python standard library; the site build additionally
needs `node`. There is nothing to `pip install` or `npm install`, and no other
checkout is required.

## `sync-upstream.py` — refresh the libraries

Syncs the mirrored library files from
[upstream](https://gitlab.com/ohwr/cern-kicad-libs).

Upstream rebuilds the libraries from CERN's Altium sources nightly, but a full
clone is ~900 MB, so this script syncs by *git blob SHA*: it lists upstream's
tree, compares it with `git ls-files -s`, downloads only the paths whose blob
differs, and verifies each download by recomputing its blob SHA. A typical day
of upstream change is a few hundred small files.

```sh
python3 scripts/sync-upstream.py --dry-run   # report what changed upstream
python3 scripts/sync-upstream.py             # apply it
python3 scripts/sync-upstream.py --verify    # hash the tree and prove it matches
python3 scripts/sync-upstream.py --ref <sha> # pin to a specific upstream commit
```

It writes `mirror-state.json` (the upstream commit this mirror reflects) and
updates the "Last sync" line in `README.md` — but only when something actually
changed, so a no-op run leaves the tree clean. Mirror-owned paths — `README.md`
body, `_site/`, `scripts/`, `.github/` — are never overwritten or deleted.

Note: upstream's `CHECKSUMS` file is **not** an MD5 of the committed KiCad
files; it fingerprints the Altium source side of the conversion, so it cannot be
used to verify a download, and it misses some files that actually changed. It is
mirrored verbatim like any other file, but the sync deliberately does not rely
on it.

## `build-site.py` — rebuild the preview site

```sh
python3 scripts/build-site.py
```

Runs the generator into a temporary directory and installs the three artefacts
the viewer loads:

- `_site/index.json` — search index (library list + per-item metadata + `generated` timestamp)
- `_site/previews/<lib>.json` — `{ symbolName: svgString }` per symbol library
- `_site/footprint-previews/<lib>.json` — `{ footprintName: svgString }` per footprint library

The generator also emits parsed `symbols/` and `footprints/` JSON (~750 MB) that
the viewer never reads; those are discarded with the temporary directory. The
viewer itself (`_site/index.html`, `style.css`, `app.js`) is hand-written and is
not touched by the build.

### `build-site.mjs` is generated

`scripts/build-site.mjs` is a committed bundle: the s-expression parsers and SVG
renderers from `scripts/build-cern-libs.ts` in
[circuitrodev/circuitro](https://github.com/circuitrodev/circuitro), rolled into
a single dependency-free ES module. That repository is private, so vendoring the
bundle is what lets this mirror rebuild its own site — previously the site could
only be regenerated by whoever had that checkout, and it silently went stale.

To refresh it after changing the generator upstream, from a circuitro checkout:

```sh
node_modules/tsx/node_modules/esbuild/bin/esbuild scripts/build-cern-libs.ts \
  --bundle --platform=node --format=esm --target=node18 --tsconfig=tsconfig.json \
  --banner:js='// Generated bundle - do not edit by hand. See scripts/README.md for provenance and how to regenerate.' \
  --outfile=<path-to-this-repo>/scripts/build-site.mjs

# esbuild copies the entry file's shebang, which is the tsx one; make it node's:
sed -i '' '1s|.*|#!/usr/bin/env node|' <path-to-this-repo>/scripts/build-site.mjs
```

Then run `python3 scripts/build-site.py` and check that `git status` shows only
the `generated` timestamp changing — the bundle is expected to reproduce the
committed previews byte for byte.

## Automation

[`.github/workflows/sync-upstream.yml`](../.github/workflows/sync-upstream.yml)
runs the sync daily, rebuilds the site when (and only when) the libraries moved,
and pushes both in one commit.
